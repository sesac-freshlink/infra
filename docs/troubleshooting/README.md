# 트러블슈팅 문서 작성법

`infra` 레포에서 겪은 장애·오류와 해결 과정을 남기는 곳이다. 같은 문제를 다시 만났을 때 이 폴더만 검색하면 바로 고칠 수 있게 쓴다.

> 구조도는 [.github 레포 docs/기획/architecture](https://github.com/sesac-freshlink/.github/blob/main/docs/기획/architecture/README.md), 기술 스택 선택 이유는 [.github 레포 docs/기획/기술스택과-선택이유.md](https://github.com/sesac-freshlink/.github/blob/main/docs/%EA%B8%B0%ED%9A%8D/%EA%B8%B0%EC%88%A0%EC%8A%A4%ED%83%9D%EA%B3%BC-%EC%84%A0%ED%83%9D%EC%9D%B4%EC%9C%A0.md)에 있다. 이 폴더(`docs/`)에는 트러블슈팅 문서만 둔다.

## 규칙

- **파일 이름:** `YYYY-MM-DD-짧은-제목.md` (날짜는 문제를 겪은 날, 제목은 띄어쓰기 대신 `-`). 예: `2026-10-14-eks-노드-NotReady.md`
- **문서 하나에 문제 하나.** 원인이 다르면 문서를 나눈다.
- **실제 오류 로그를 코드 블록으로 붙인다.** 요약만 쓰지 말고, 검색되도록 핵심 메시지는 원문 그대로 둔다. 너무 길면 앞뒤를 자르고 `...`로 표시한다.
- **비밀값은 가린다.** AWS 계정 ID, 액세스 키, 토큰, 비밀번호, DB 접속 주소, Cognito 클라이언트 ID 등은 `<ACCOUNT_ID>`, `****`처럼 바꾼다. 커밋 전에 한 번 더 확인한다.
- **관련 이슈·PR·커밋을 링크한다.** 해결 커밋이나 PR이 있으면 꼭 단다.
- 명령은 그대로 따라 칠 수 있게 쓴다 (`terraform`, `kubectl`, `aws` 명령과 실행한 폴더).
- 평이한 한국어 문장(`~한다` 체)으로 쓴다.

## 템플릿

아래를 복사해 새 파일을 만든다.

````markdown
# <한 줄 제목: 무엇이 어떻게 안 됐나>

- 날짜: YYYY-MM-DD
- 작성: <이름>
- 관련: <이슈/PR/커밋 링크>

## 증상

무엇이 안 됐는지. 실제 오류 메시지를 붙인다.

```text
<오류 로그 원문 — 비밀값은 가린다>
```

## 환경·발생 조건

- 묶음/위치: `persistent/` 또는 `cluster/`, 모듈 이름
- 도구 버전: Terraform, AWS provider, kubectl 등
- 어떤 작업 중이었나: 예) 월요일 `cluster` apply 직후, 금요일 destroy 중

## 원인

왜 그랬는지. 확인한 방법(명령, 콘솔 화면, 문서)도 함께 쓴다.
````
